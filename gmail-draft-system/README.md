# Gmail下書き自動作成システム

スプレッドシート上でチェックボックスをクリックするだけで、Geminiが対象の会社名・氏名をリサーチし、さらに高橋のGmail内にある過去のやり取り履歴も踏まえて件名・本文を生成し、Gmailの下書き（署名なし・件名に「相談」を含まない）を自動作成する仕組みです。冒頭の挨拶文と末尾の日程調整リンクは固定文で、リサーチ結果・過去のやり取りは本文中盤にのみ反映されます。

## 構成

```
gmail-draft-system/Code.gs   スプレッドシートに設定するApps Scriptコード
```

## セットアップ手順

### ステップ1：スプレッドシートの準備

1. 新規のスプレッドシートを作成し、画面下部のシート名を `送信リスト` に変更する。
2. 1行目に以下の見出し（ヘッダー）を入力する。
   - A1：会社名
   - B1：氏名
   - C1：メールアドレス
   - D1：ドラフト作成
   - E1：ステータス
3. **D列（D2以下）**を選択し、メニューの「挿入」＞「チェックボックス」をクリックして、チェックボックスを配置する。

### ステップ2：GAS（Google Apps Script）の記述

1. スプレッドシートのメニューから「拡張機能」＞「Apps Script」をクリックする。
2. 最初から入力されている `function myFunction() { }` を消して、[`Code.gs`](./Code.gs) の内容を貼り付ける。
3. コードを貼り付けたら、エディタ上部の「フロッピーディスクのアイコン（プロジェクトを保存）」をクリックして保存する。

### ステップ3：Gemini APIキーの設定（重要）

企業・担当者のリサーチにGemini APIを使用するため、APIキーをスクリプトに設定する必要がある。

1. [Google AI Studio](https://aistudio.google.com/apikey) などでGemini APIキーを発行する。
2. Apps Scriptの画面左側にある「歯車アイコン（プロジェクトの設定）」をクリックする。
3. 「スクリプト プロパティ」欄で「スクリプト プロパティを追加」をクリックし、以下を設定して保存する。
   - プロパティ：`GEMINI_API_KEY`
   - 値：発行したAPIキー

### ステップ4：トリガーの設定（重要）

Gmailおよび外部API（Gemini）へのアクセス権限を付与するため、手動でトリガーを設定する必要がある。

1. Apps Scriptの画面左側にある「時計のアイコン（トリガー）」をクリックする。
2. 画面右下の青いボタン「トリガーを追加」をクリックする。
3. 以下の設定にして「保存」をクリックする。
   - 実行する関数を選択：`createDraftOnEdit`
   - 実行するデプロイを選択：`Head`
   - イベントのソースを選択：スプレッドシートから
   - イベントの種類を選択：編集時
4. 初回保存時のみ、「アクセスを承認」というポップアップが出る。
   - ご自身のGoogleアカウントを選択する。
   - 「このアプリは Google に確認されていません」と出たら、左下の「詳細」をクリックし、一番下の「○○（プロジェクト名）に移動（安全ではないページ）」をクリックする。
   - 次の画面で「許可」をクリックする（Gmail・外部サービスへの接続の両方の権限を許可する）。

※ 既存のシステムから今回のコードに更新した場合、外部API呼び出し（`UrlFetchApp`）が新たに追加されているため、再度この承認フローが必要になる。

## 使い方

1. スプレッドシートの「A列:会社名」「B列:氏名」「C列:メールアドレス」を入力（またはコピペ）する。
2. 下書きを作成したい行の **D列（ドラフト作成）** のチェックボックスにチェックを入れる。
3. 2〜3秒後に、E列のステータスが「作成済み」に変わり、チェックボックスのチェックが自動で外れる。
4. Gmailの「下書き」フォルダを開くと、Ccや件名・本文がセットされた下書きが作成されている。

過去のやり取りがあった相手など、個別に文章をカスタマイズしたい場合は、自動で作成されたGmailの下書きを開いて、送信前に一部を書き換える運用にすると一番スムーズ。

## 本文の構成

| 部分 | 内容 | 生成方法 |
| --- | --- | --- |
| 冒頭の挨拶 | 「お世話になっております。株式会社森未来の高橋です。」 | 固定文（変更されない） |
| 中盤 | 過去のやり取りを踏まえた一言(あれば)＋会社の特徴や木材活用の提案、情報交換の依頼 | Geminiが会社名・氏名のリサーチとGmail履歴を踏まえて生成 |
| 末尾 | 日程調整の案内とリンク1・リンク2 | 固定文（変更されない） |

件名も「【会社名・氏名様】〈Geminiが生成したフレーズ〉　森未来/髙橋」の形式で、「相談」という語は使わない。

## Gmail内の過去のやり取り履歴について

`getGmailHistorySummary()` が、C列のメールアドレスを **From・To・Ccのいずれか** に含むスレッドを高橋のGmail内から最大5件検索し、日付・件名・本文抜粋をGeminiに渡す。履歴が見つかった場合、Geminiは「以前はご来社いただきありがとうございました」のような一言を本文中盤の冒頭に加える。見つからなければ、初めての連絡として通常どおり作成する。

**重要な制約**：これは「高橋自身のGmailメールボックスに実際に届いているメールを検索する」仕組みであり、森未来の他メンバーのメールボックスを横断的に検索するものではない。他メンバーが顧客とやり取りする際に高橋または共有アドレス（`marketing@shin-mirai.co.jp` など）をCcに入れていれば、そのやり取りは高橋のメールボックスにも届くため、この検索でヒットする。逆に誰もCcしていない他メンバー単独のやり取りは対象外。

森未来の全メンバーの送受信履歴を横断的に参照したい場合は、Google Workspace管理者による「ドメイン全体の委任」を使った別方式（サービスアカウント経由で複数メールボックスにアクセスする仕組み）が必要になり、本スクリプトの範囲を超える大掛かりな設定となる。

## 注意事項

- 対象シート名は `送信リスト` 固定（`Code.gs` 内の判定条件を変更すれば別名にも対応可）。
- Ccは `marketing@shin-mirai.co.jp` 固定（宛先を変更したい場合は `Code.gs` の `GmailApp.createDraft` の第4引数を編集する）。
- E列がすでに「作成済み」の行はスキップされ、チェックのみ自動で外れる。
- エラーが発生した場合はE列に「エラー: 」に続けて内容が記載される（Gemini APIキー未設定・APIエラー・応答解析失敗などもここに表示される）。
- Geminiのリサーチ結果はWeb上の公開情報の範囲に限られるため、生成された本文は下書きの段階で必ず内容を確認し、必要に応じて手直ししてから送信すること。
