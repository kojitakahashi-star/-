# アポ返信メール一括作成

アポ取りメールを大量に送っていて、返信や予約への対応が追いついていない状態を解消するスキル。
Claude が Gmail とカレンダーから「返信が必要なもの」を拾って一覧にし、ユーザーはチェックを付けるだけ。
選ばれたものについて、アポ取りスレッドに続く形で Gmail の下書きを作る。

会社固有の設定(アポ取りメールの件名、日程調整リンク、訪問可能エリアなど)は同じフォルダの `config.md` を最初に読むこと。

## 守ること

- **送信は絶対にしない。** `create_draft` で下書きを作るところまで。`send_message` / `reply` は使わない。
- カレンダーの予定を変更する(Meet リンクを付ける等)ときは、ユーザーが一覧で選んだ時点で了承済みとみなしてよいが、
  `update_event` は必ず `notificationLevel: "NONE"` で呼び、相手にカレンダーからの通知メールが飛ばないようにする。
- 本文に事実として書くのは、メール・カレンダー・会社 DB・Web で確認できたことだけ。日時は必ずカレンダーの予定から取る(メール本文の日時と食い違ったら一覧で警告する)。
- スレッドは長い(引用が何重にも入る)ので、候補の洗い出しは `MINIMAL` / `METADATA_ONLY`、本文を読むのは候補に絞ってから `PLAIN_TEXT` で。

## 手順

### 1. 返信待ちの候補を集める

対象期間は既定で直近 `config.md` の「さかのぼる日数」。ユーザーが期間を指定したらそれに従う。

**1-A. 相手から返信が来ているスレッド(Gmail)**

`search_threads` で `config.md` の「アポ取りメールの検索クエリ」を実行する(`-from:me` を付けて相手からの返信があるものに絞る)。
各スレッドを `get_thread`(`MINIMAL`)で開き、**最新メッセージの送信者が自分以外**のものだけ残す(自分が最後に返信済みなら対象外)。
自分が最後でも、相手の最新メールより後に自分の下書きがある場合も対象外(`list_drafts` で threadId を照合)。

**1-B. カレンダー予約だけ入っている人(Calendar)**

`list_events` を今日〜`config.md` の「先の予定を見る日数」で取り、`config.md` の「予約ページの予定タイトル」に一致する予定を拾う。
各予定から次を控える。

- 予約者名・メールアドレス(説明欄の「予約者:」の下、または attendees のうち自分以外)
- 日時(start / end)
- **予約が入った日時 = `created`**(一覧に「10/23 予約」のように出す)
- Meet リンクの有無(`hangoutLink` / `conferenceData`。`list_events` で出なければ `get_event` で確認)

その予約者のメールアドレスで Gmail を検索し(`from:<addr> OR to:<addr> newer_than:60d`)、
**予定の `created` 以降に自分から相手へ送ったメールがあれば、もう連絡済みなので対象外**。
相手から予約の連絡メールが来ている場合は 1-A 側で拾われるので、1-B では重複させない(1-A を優先)。

**1-C. 未予約のアポ確定(カレンダー予定はあるが予約ページ経由でない)**

1-A のスレッドで、相手が日時を指定しているのにカレンダーに該当日時の予定がない場合は、一覧で「⚠ カレンダー未登録」と警告する。予定作成は勝手にしない。

### 2. 各候補を分類する

1-A のスレッドは最新の相手メールを `PLAIN_TEXT` で読み、次のどれかに分類する。

| 区分 | 判定 | 返信の方向性 |
|---|---|---|
| ① 予約のみ | 1-B で拾った、メール連絡なしの予約 | 予約のお礼+「〇月〇日(〇) 〇:〇〇〜 よろしくお願いします」 |
| ② 予約済み・オンライン希望 | 「予約しました/設定しました」+「オンライン/ウェブ/Web/Meet/Zoom/リモート」 | お礼+Meet リンク+当日よろしく |
| ③ 予約済み・形式未指定 | 「予約しました」等があり、形式の指定なし | 会社所在地を調べ、訪問可能エリアなら訪問打診、エリア外なら Meet リンク |
| ④ 予約済み・来社/訪問希望 | 「来社」「ご訪問」「お越し」など | お礼+訪問の確認(住所・受付方法を尋ねる) |
| ⑤ その他 | 日程の相談、質問、辞退、ニーズなし など | 一覧には出すが既定は「自分で書く」。選ばれたら要旨を踏まえた返信案を作る |

予約したと書いてあるのにカレンダーに該当予定が見つからない場合は、区分の横に「⚠ 予定未確認」と付ける。

### 3. 会社所在地を調べる(区分 ③ のみ、①でも訪問打診を選んだ場合)

次の順で所在地を確定する。見つかった時点で止める。

1. 会社 DB: `python3 scripts/query_company.py "<会社名>"` の「本社所在地」(会社名の揺れに注意。見つからなければ一覧表示から近いものを探す)
2. 相手のメール署名(住所・電話番号の市外局番 03 など)
3. メールアドレスのドメインのコーポレートサイトを WebFetch(会社概要ページ)
4. Web 検索「<会社名> 所在地」

`config.md` の「訪問可能エリア」に入るかを判定し、一覧に「東京都品川区 → 訪問打診」「大阪府 → オンライン」のように根拠ごと出す。
判定できなかったら「所在地不明 → オンライン」として一覧に出し、ユーザーに選ばせる。

### 4. 一覧を見せて選んでもらう(ぽちぽち)

まずチャットに一覧表を出す(番号・区分・相手(会社/氏名)・予約日時・予約が入った日・所在地判定・提案アクション)。
続けて **AskUserQuestion の複数選択** で「下書きを作るもの」を選んでもらう。

- 1つの質問に選択肢は4つまでなので、区分ごとに質問を分ける(① / ② / ③④ / ⑤)。1回の AskUserQuestion で最大4問=16件。
  それを超える場合は、予約日時が近い順に16件ずつ繰り返す。
- 選択肢ラベル: `<姓>様(<会社名>)`、説明: `11/9(月)13:30〜 / 10/23予約 / 提案: Meetリンク送付`
- ③ で訪問打診になっているものは、説明に「訪問打診(品川区)」と出し、ユーザーがオンラインに切り替えたい場合は「Other」に書いてもらう。
- 何も選ばれなかった区分はスキップ。

### 5. Meet リンクを用意する(②、③のオンライン、①でオンラインのもの)

- 予定にすでに Meet リンクがあればそれを使う。
- なければ `update_event`(`eventId`、`addGoogleMeetUrl: true`、`notificationLevel: "NONE"`)で発行し、返ってきた `hangoutLink` を使う。
- 予定が見つからない(⚠ 予定未確認)ものは Meet を発行せず、本文にリンクを入れない版で下書きを作り、報告で知らせる。

### 6. 下書きを作る

返信先は **アポ取りスレッドの最新メッセージ**。

- 1-A 由来: そのスレッドの最新メッセージ ID
- 1-B 由来: 予約者アドレスで `subject:(<config の件名キーワード>) (to:<addr> OR from:<addr>)` を検索してアポ取りスレッドを特定し、その最新メッセージ ID。
  見つからなければ「予約が完了しました」メールのスレッドではなく、**新規メール**(件名は `config.md` の「新規作成時の件名」)にする。

`create_draft` の引数:

- `replyToMessageId`: 上記(新規なら省略)
- `to`: 相手のアドレス / `cc`: スレッドの CC をそのまま(自分は除く。`config.md` の「常に CC に入れるアドレス」は必ず残す)
- `subject`: 元スレッドの件名に `Re: `(すでに付いていればそのまま)
- `includeSignature`: false(ユーザーの返信スタイルは本文末尾を「高橋」で締め、長い署名を付けない。`config.md` で変更可)
- `body`: プレーンテキスト、Markdown 記号なし

日時の書き方: `11月9日(月) 13:30〜14:30`(カレンダーの値から作る。曜日も計算して付ける)

本文テンプレート(`config.md` の「名乗り」「締め」を使う。相手の書き出しが「株式会社森未来 高橋様」形式でも、こちらは `<姓>様` だけでよい):

**① 予約のみ**
```
<姓>様

お世話になっております。
株式会社森未来の高橋です。

この度は日程調整のご予約をいただき、誠にありがとうございます。
<日時>にて承りました。

【オンラインの場合】
当日は下記のリンクよりお入りいただけますと幸いです。
Google Meet:<Meet URL>

【訪問打診の場合】
<所在地の区など>でしたら、もしよろしければ当日は御社へご訪問させていただくことも可能でございます。
ご訪問が難しい場合は、オンラインにて実施させていただきます。
(オンラインの場合のリンク:<Meet URL>)

当日はどうぞよろしくお願いいたします。

高橋
```

**② 予約済み・オンライン希望**(ユーザーの実際の返信がこの形)
```
<姓>様

ご調整いただき誠にありがとうございます。
承知しました。

オンラインリンクは下記となります。
お時間になりましたらお入りいただけますと幸いです。

<日時>
Google Meet:<Meet URL>

大変ご多用のところ恐れ入りますが、ご確認いただけますと幸いです。
当日はどうぞよろしくお願いいたします。

高橋
```

**③ 予約済み・形式未指定 → 訪問打診**
```
<姓>様

ご調整いただき誠にありがとうございます。
<日時>にて承知しました。

もしご迷惑でなければ、当日は御社へご訪問させていただけないでしょうか。
実際の木材サンプルなどもお持ちしながらお話しできればと考えております。
ご訪問が難しい場合は、下記のオンラインリンクにて実施させていただきます。

Google Meet:<Meet URL>

お手数ですが、ご訪問の可否をご教示いただけますと幸いです。
当日はどうぞよろしくお願いいたします。

高橋
```
(エリア外と判定された③は②のテンプレートを使う)

**④ 来社/訪問希望**
```
<姓>様

ご調整いただき誠にありがとうございます。
<日時>にて承知しました。

当日は御社へお伺いさせていただきます。
念のため、ご訪問先のご住所と受付方法をご教示いただけますと幸いです。
(DB 等で住所が確認できている場合は「<住所>へお伺いする認識でおりますが、お間違いないでしょうか。」に置き換える)

当日はどうぞよろしくお願いいたします。

高橋
```

**⑤ その他** は相手メールの要旨に沿って短く返す。日程の再相談なら `config.md` の日程調整リンクを再掲する。辞退・ニーズなしなら、お礼+今後の情報提供(イベント案内など)で締める。事実を推測で書かない。

### 7. 結果を報告

作った下書きを表で報告する: 相手 / 区分 / 日時 / Meet 発行の有無 / 下書きリンク(`viewUrl`)。
スキップしたもの・⚠ が付いたもの(予定未確認、カレンダー未登録、所在地不明)は別にまとめる。

最後に「内容を確認して Gmail から送信してください。修正があればここで指示してください」と添える。
修正指示があれば `update_draft` で同じ下書きを更新する。
