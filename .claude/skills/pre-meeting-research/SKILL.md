# 商談前リサーチ → 外報への挿入 → 顧客フォルダ確認

ユーザーは **相手の名前と所属企業** を書くだけ。Claude が調べてまとめ、外報ページに書き込み、Drive の顧客フォルダを用意する。

ID・URL・命名ルールなどの設定は同じフォルダの `config.md` を最初に読むこと。

## 守ること

- 書き込むのは外報ページの **「先方の基本情報」欄だけ**。アポ背景・提案仮説・商談ゴール・議事録などには触れない(ユーザーが書く欄)。
- 「先方の基本情報」にすでにユーザーが書いた内容があれば消さない。その下にトグルを追加する。プレースホルダー `〜〜〜` だけのときは置き換える。
- 事実として書くのは、出典(URL・メール・Slack・Notion)で確認できたことだけ。推測は「〜と思われます」と明記する。媒体で数字が食い違うときは併記する。
- Drive は **フォルダ作成のみ**。既存フォルダの名前変更・移動・削除・共有設定の変更はしない。
- ユーザーから「まだリサーチしなくていい」と言われているときは着手しない。

## 手順

### 1. 入力の確認

ユーザーのメッセージから取り出す。足りなければ1回だけまとめて聞く。

- 相手の名前(例: 室井様 / 室井竜也)
- 所属企業(部署・役職はあれば)

### 2. 外報ページを特定する(Notion)

先にページを見つけ、そこに載っている商談日・Slack スレッド・カレンダーを以降のリサーチの手がかりにする。

- `config.md` の Sales Agent データソースを SQL で検索する。
  `SELECT url, "名前", "date:商談日:start", "SlackスレッドURL", "カレンダーURL" FROM "<data source>" WHERE "名前" LIKE ?`
  パラメータは法人格(株式会社・(株)・有限会社など)と空白を外した社名の一部で `%<社名>%`。
- ヒットが1件ならそのページ。複数(同じ会社で別商談)なら、商談日が今日以降で一番近いものを第一候補にして選択肢で確認する。
- 0件なら、表記ゆれ(カタカナ/英字、「・」の有無)で再検索。それでも無ければユーザーに伝え、「ページが作られるのを待つ」か「ページURLを教えてもらう」かを選んでもらう(リサーチ結果はチャットに残す)。
- ページを `fetch` し、「先方の基本情報」欄の現状を確認する。

### 3. 社内リサーチ

並列で実行してよい。

- **Gmail**: `"<社名>" OR "<姓>"` で検索 → アポ取りのスレッドを `get_thread`(PLAIN_TEXT)で全文確認。
  拾うもの: 相手の正式な部署・役職・氏名(署名欄)、メールアドレス・住所、日程・形式(Meet / 訪問)、**先方からの要望・関心**(「〜の事例を聞きたい」など)、アポのきっかけ。
- **Slack**: 外報ページの SlackスレッドURL のスレッドを読む。加えて社名で `slack_search_public_and_private`(過去の取引・紹介・問い合わせを探す)。
- **Notion**: 社名で `search`。過去の議事録・提案データベース・同じ会社の別の外報ページがあれば要点を拾う(すがたかたちのページの「過去のお取引事例」のように、取引実績は特に重要)。
- **Drive**: 顧客フォルダ(手順7と同じ方法)にある過去資料のタイトルを確認する(中身を全部読む必要はない)。
- **カレンダー**: 外報ページのカレンダーURLがあれば予定の説明・同席者を確認。

### 4. ネットリサーチ

`WebSearch` を使う(この環境では WebFetch で開けないサイトが多い。`config.md` の「既知の制約」参照)。

記入済みの外報ページ(`config.md` の「手本ページ」)と同じ観点で集める。

1. **何の会社か(一言)** — 例:「展示会ブースを主力とする空間プロデュース会社」
2. **主力事業・メイン領域**
3. **事業の広がり・注力領域(最近の動き)** — 新規事業、出展、プレスリリース、受賞
4. **会社概要** — 本社所在地、代表者、設立、資本金、従業員数、売上、拠点
5. **主な実績・事例** — 森未来の商材(木材調達・内装木質化・不燃木材・認証材・什器製作など)と関わりそうなものを優先
6. **設備・内製体制**(製造・施工系の会社の場合)
7. **木材・サステナビリティとの接点** — 木質化・国産材・FSC・脱炭素などの取り組み
8. **相手個人** — 公開されているインタビュー・登壇・SNS(見つかった場合のみ。私的な情報は書かない)

検索の例: `<正式社名> 会社概要` / `<社名> 事業内容 実績` / `<社名> プレスリリース 2026` / `<社名> 木材 OR 木質化 OR 国産材` / `<社名> <姓> インタビュー`。
同名の別会社に注意し、住所・ドメイン(メール署名のドメインと一致するか)で同一性を確かめる。

### 5. まとめをチャットで報告

書き込む前に、トグルに入れる内容をチャットで簡潔に示す(箇条書き)。ユーザーの確認待ちはせず、そのまま手順6へ進んでよい。

### 6. 外報ページへトグルで挿入

`update-page`(`update_content`)で「先方の基本情報」欄だけを置き換える。形は次のとおり(`config.md` の「挿入テンプレート」を使う)。

- 1行目(黄色背景の箇条書き): `<会社名>｜<部署> <役職>`
- 2行目: `<氏名> 様`
- その下に **トグルを2つ**:
  - `会社情報(ネットリサーチ)` — 手順4の結果。各項目は「<b>見出し的な一文</b>。補足。 [出典ドメイン](URL)」の形(アートフリークのページと同じ書き方)
  - `社内情報(Gmail・Slack・Notion)` — アポの経緯、先方の要望・関心、過去の接点(無ければ「見つかりませんでした(初回接点)」と書く)

注意:
- トグルは箇条書き `<li>` で包まない(空の箇条書きが1行できてしまう)。「先方の基本情報」の `<ul>` を閉じた直後に、親 `<li>` の子として置く。
- 書き込んだら一度 `fetch` して、空行(`<p />` だけの箇条書き)や崩れが無いかを確認する。崩れていたら直す。

### 7. Drive の顧客フォルダを確認・作成

`config.md` の「顧客フォルダの親フォルダ」の直下を確認する。

- `search_files` で `parentId = '<親フォルダID>' and mimeType = 'application/vnd.google-apps.folder' and title contains '<中核の社名>'` を検索する。
  中核の社名は法人格を外したもの(例:「エクス・アドメディア」)。ヒットしなければ、「・」や空白を外した形、英字表記、略称でも検索する。
- **あれば作成しない**。見つかったフォルダ名とリンクを報告する。似た名前が複数あれば一覧で報告するだけにする。
- **無ければ作成する**: `create_file`(`contentMimeType: application/vnd.google-apps.folder`, `parentId`: 親フォルダID)。フォルダ名は `config.md` の命名ルールに従う。

### 8. 結果を報告

- 外報ページのリンクと、挿入した内容の要約
- Drive フォルダ: 「既存: <名前>(リンク)」または「新規作成: <名前>(リンク)」
- 調べられなかったこと(開けなかったサイト、媒体で食い違った数字など)
- 出典URLの一覧
